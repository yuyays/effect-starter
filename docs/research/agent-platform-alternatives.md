# Optional agent application layer: alternatives

Researched 2026-11-06. Primary documentation and source inspection only; no implementation, deployments, benchmarks, or independent reviewer. No further delegation, as requested. Recommendations below are architectural judgments, not vendor guarantees.

## Recommendation for this starter

Ship a **separate, optional domain-agent example first**, rather than adding an agent runtime to the base. Consider a generator preset after the example proves useful. The current README promises Effect v4, PostgreSQL, Node/Bun, and no configured host. `apps/api/src/main.ts` owns execution; `db/client.ts` exposes an Effect service; `services/users.ts` composes backend work directly in Effect. Preserve that shape and PostgreSQL default.

An agent application layer should own runs, typed tools, approvals, progress, cancellation, and recovery. Model inference, durable orchestration, domain storage, and coding sandboxes are separate choices. Do not make a coding harness the required runtime for an ordinary business agent.

For an initial SaaS example with multi-day approvals and external writes, evaluate **Temporal with a separate Node worker**. For a project explicitly choosing Cloudflare and per-entity real-time interaction, evaluate **Agents plus Workflows**. For a local coding harness, SQLite and a local SDK host can be simpler. These solve different deployment problems; none is a universal winner.

## Execution and hosting tradeoffs

**Temporal TypeScript.** Workflow code is replayed deterministically; model calls, database access, tools, and child processes belong in Activities, not the Workflow sandbox. Completed Activity results are recorded, but an attempt can repeat if its completion was lost. Use Signals/Updates and durable conditions for approval waits, and Continue-As-New to bound long-lived history. Temporal now documents TypeScript integrations for both Vercel AI SDK and OpenAI Agents SDK; a hand-written monolithic “agent Activity” is not the only option. The latter integration keeps orchestration in the Workflow and model/MCP/sandbox I/O in Activities. These are Temporal integration claims, not independent OpenAI guarantees. [Workflow constraints](https://docs.temporal.io/develop/typescript/workflows/basics), [AI SDK recipe](https://docs.temporal.io/ai/cookbook/ai-sdk-by-vercel-typescript), [Temporal integration reference](https://docs.temporal.io/develop/typescript/integrations/openai-agents), [approval pattern](https://docs.temporal.io/design-patterns/approval).

Temporal requires a coordinating service plus deployed application workers. Cloud runs the service; it does not eliminate worker hosting. Self-hosting is available, reducing hosting-provider dependence while retaining substantial dependence on Temporal APIs, history semantics, and deployment/versioning rules. Operational cost and a second programming model are real costs for this small starter. Keep Effect services inside Activity implementations and use explicit worker/SDK boundaries; do not assume arbitrary Effect code is replay-safe. Node is the conservative example target: the inspected official agent sample requires Node 22+, and this research did not verify Bun worker support. [Production deployment](https://docs.temporal.io/production-deployment), [sample prerequisites](https://github.com/temporalio/samples-typescript/tree/fe81f3b2e93f295ba3cbbb91be875281701a7d52/openai-agents).

**Cloudflare has three distinct layers:**

- **Durable Objects (DOs):** identity-addressed actors with private, transactional storage. SQLite-backed DO storage is a database per object, not a shared PostgreSQL replacement, not D1, and not a downloadable local SQLite-file hosting model. Cloudflare recommends SQLite-backed namespaces for new objects. Persisted data survives object recreation; a live closure does not. [Storage API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [DO lifecycle/FAQ](https://developers.cloudflare.com/durable-objects/reference/faq/).
- **Agents SDK:** an application framework running on DOs, adding state synchronization, real-time connections, schedules, and agent lifecycle facilities. Current docs also expose `runFiber`/`startFiber`, SQLite checkpoints, status, deduplicated acceptance, and cooperative cancellation. Recovery calls an application hook: it cannot automatically replay the original closure. This is more than chat persistence, but differs from automatic step replay. [Runtime](https://developers.cloudflare.com/agents/runtime/), [durable fibers](https://developers.cloudflare.com/agents/agent-class/durable-execution/).
- **Workflows:** separately instantiated, durable multi-step jobs with persisted step results, retries, sleep, and event waits. They can run without Agents. `AgentWorkflow` connects them to an originating Agent; use the Agent for interaction and the Workflow for independently recoverable processing. `waitForEvent`/approval events avoid holding an HTTP connection open. [Integration](https://developers.cloudflare.com/agents/concepts/workflows/), [events](https://developers.cloudflare.com/workflows/build/events-and-parameters/).

Cloudflare offers less infrastructure to operate and a natural per-customer/case actor boundary. Its bindings, object routing, workflow APIs, storage access, and deployment model create stronger hosting coupling. Cross-object reporting and atomic operations spanning objects require deliberate aggregation/coordination. Adding it to this starter means an explicit runtime/deployment alternative, not simply replacing the SQL connection string. SQLite data format portability does not make the distributed service portable. Workflows steps still need idempotent external API calls. [Workflow rules](https://developers.cloudflare.com/workflows/build/rules-of-workflows/).

## SQLite versus PostgreSQL

For a local, single-owner harness, SQLite avoids a database daemon and suits transcripts, run records, and workspace metadata. It can also serve multi-user applications through one application server or sharded databases; “SQLite cannot do SaaS” is incorrect. Its one-writer-per-file constraint and direct network-filesystem sharing are the relevant limits. [SQLite's own suitability guide](https://sqlite.org/whentouse.html).

For this starter's multi-user domain-agent SaaS, retain PostgreSQL as the shared system of record: tenant membership, cases, approvals, uniqueness constraints, and cross-tenant operational reporting usually need shared relational transactions and concurrent access. PostgreSQL's MVCC and row locking support that shape, though contention and tenant authorization still require design. DO-per-case SQLite can instead scale independent actors horizontally; shared reporting and cross-case consistency become separate problems. A database choice alone supplies neither durable orchestration nor process recovery. [PostgreSQL concurrency model](https://www.postgresql.org/docs/current/mvcc-intro.html), [DO private storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).

## Approval, restart, and idempotency contracts to borrow

Persist the proposed action and arguments, tenant, resource version, approving identity, expiry, and terminal decision. Authenticate the approval endpoint; bind approval to that exact action and recheck authorization/preconditions before committing. An SDK permission callback or a pending Promise is not a durable business approval record. Treat this paragraph as a proposed application contract.

Separate job acceptance from execution and execution from completion. Use a stable business operation key, a transactional intent/outbox where appropriate, and downstream idempotency keys or reconciliation. A refund can succeed immediately before a worker crashes: replay must discover or reuse that refund, not issue another. Recorded step completion prevents completed work replay; it does not make an external write and checkpoint one atomic transaction. Model calls may also repeat and incur cost before completion is recorded. [Temporal Activity semantics](https://docs.temporal.io/activity-definition), [Cloudflare retry/idempotency guidance](https://developers.cloudflare.com/workflows/build/rules-of-workflows/).

Own workers, streams, SDK sessions, and subprocesses in scopes with finalizers and failure reporting. Propagate cancellation into SDK abort signals and process trees where supported. With Temporal, long-running Activities need heartbeats for failure detection and cancellation delivery; an Activity timeout does not itself kill a shell process. Define restart behavior for unknown outcomes and interrupted children; do not silently resume a previously approved but changed action. [Temporal heartbeats/cancellation](https://docs.temporal.io/develop/typescript/activities/timeouts).

## Coding SDK deployment constraints

- **Codex:** official OpenAI guidance distinguishes bounded `codex exec` jobs, the SDK for starting/resuming/streaming tasks, and app-server for persistent conversations and approval handling through a local Codex process. Plan a process-capable execution host for the local harness integration. This is distinct from managed Agents API execution; OpenAI's Cloudflare example puts its executor in a **Container**, coordinated by a Worker. [Official integration guidance](https://developers.openai.com/blog/codex-as-a-platform), [Cloudflare executor architecture](https://developers.openai.com/api/docs/guides/agents-api/environments/providers/cloudflare). The old SDK documentation URL redirected outside the requested OpenAI source domains; no SDK subprocess implementation claim is based on that redirected page.
- **Claude Agent SDK:** spawns a CLI subprocess over stdio, with working directory and disk transcripts. Concurrent sessions consume separate process trees. Containers/sandbox hosts need filesystem persistence, per-tenant isolation, credentials, and shutdown handling; restoring a transcript does not restore a running process. [Official hosting reference](https://code.claude.com/docs/en/agent-sdk/hosting).
- **Pi:** its current official SDK embeds in a Node/Bun process; a CLI subprocess is optional, unlike a mandatory SDK transport. Default tools/resources and persistent sessions still assume host capabilities. File/bashtool access needs an appropriate host and isolation; a core model loop with custom HTTP tools is a different integration. The old `badlogic/pi-mono` repository currently redirects to `earendil-works/pi`. [Official SDK](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md).

Workers' `node:child_process` compatibility module is a **stub**, not OS process execution. Thus do not infer that Node compatibility lets an Agent/Workflow directly host these CLI processes. Use a container/remote executor, or a direct model API with domain tools. Durable orchestration does not preserve a killed SDK child or its workspace automatically. [Cloudflare compatibility reference](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-nodechild_process-module).

## Two bounded domain examples to evaluate

1. **Support refund assistant:** read one tenant's ticket/order, propose a policy-limited refund, wait for an authorized human, execute one idempotent refund, record its receipt. Exclude arbitrary shell access and autonomous policy changes. Temporal illustrates the durable approval boundary; PostgreSQL holds domain records. Acceptance: restart during approval preserves the proposal; duplicate approval/webhook delivery and a crash after refund success produce one refund; changed order state invalidates approval. This is a proposed starter example, grounded in the [approval pattern](https://docs.temporal.io/design-patterns/approval) and [payment idempotency failure case](https://docs.temporal.io/activity-definition).
2. **Document intake/review agent:** extract fields from one document, validate against a schema, ask a reviewer to resolve ambiguity, then publish one approved record. Exclude a general research browser and multi-agent delegation. A DO/Agent can own case interaction and a Workflow processing stages. Acceptance: a processing retry preserves completed extraction, a new document version requires new approval, and expired/rejected cases never publish. Cloudflare's [human-in-the-loop image tagging example](https://developers.cloudflare.com/workflows/examples/wait-for-event/) is a narrower runnable analogue; it is not itself a full reasoning agent.

## Maturity and unresolved evidence

Cloudflare Workflows and SQLite-backed DO storage have GA announcements dated 2025-04-07; that does not establish identical maturity for every newer Agents SDK feature. Fiber and integration docs changed in October 2026. Temporal's current TypeScript integration marks streaming and sandbox support experimental. T3 Code and OpenCode source paths are moving quickly; inspected source is reference material, not an adoption/support guarantee. [Workflows GA](https://developers.cloudflare.com/changelog/post/2025-04-07-workflows-ga/), [SQLite DO GA](https://developers.cloudflare.com/changelog/post/2025-04-07-sqlite-in-durable-objects-ga/), [current fibers](https://developers.cloudflare.com/agents/agent-class/durable-execution/), [Temporal feature support](https://docs.temporal.io/develop/typescript/integrations/openai-agents).

No evidence gathered here establishes this starter's Effect v4 interoperability, Bun worker compatibility, workload costs, latency, recovery guarantees under its deployment, or tenant isolation. Before promoting an example to a preset, prove the restart/idempotency contracts above and document the chosen host. Borrow typed boundaries, durable acceptance, explicit approval state, and recovery policy; defer a universal provider abstraction, generic event-sourced platform, and coding-workspace manager until an actual application needs them.
