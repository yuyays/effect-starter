# Similar repositories

Researched 2026-11-07 against first-party GitHub READMEs, manifests, and selected source files. This is a source comparison, not an install or production-readiness audit. Versions describe the inspected source; repository names alone do not establish equivalence.

## Effect generators and enforced architecture: independent review additions

The first pass emphasized dependencies and application layout. Independent review found closer peers for scaffolding and enforced conventions. The stack list below is not an overall ranking.

- **[lloydrichards/stack-effect](https://github.com/lloydrichards/stack-effect)** is a direct Effect-first generator peer. It scaffolds a monorepo, offers Node/Bun selection, and adds client/server/CLI/package targets through composable modules. Its React HTTP-client module also adds the corresponding server module. Its interface centers on incrementally composing modules rather than selecting our complete frontend presets. Sources: [README](https://github.com/lloydrichards/stack-effect/blob/main/README.md), [coding-agent guide](https://stack-effect.lloydrichards.dev/use-with-coding-agents.md).
- **[deracs/create-effect-project](https://github.com/deracs/create-effect-project)** is another direct generator peer: Effect v4, Node/Bun, HttpApi and TanStack Start full-stack templates, plus CLI, AI, and Cloudflare templates. Its README documents default Effect compiler diagnostics and Oxlint, including typecheck failure for floating Effects, with stricter rules through `--slop`. This substantially overlaps with our generator and guardrail goals. Its documented template selection differs from our React/Vue/API-only frontend matrix. Source: [README](https://github.com/deracs/create-effect-project/blob/main/README.md).
- **[PatrickOgilvie/popcomputer-web](https://github.com/PatrickOgilvie/popcomputer-web)** is a strong enforcement comparison. It documents custom rules for Effect execution, server/client boundaries, database operations, and mutable state, alongside an agent fence and gates. These are relevant precedents for enforced architecture, although the framework differs from our application generator. Sources: [lint rules](https://github.com/PatrickOgilvie/popcomputer-web/blob/main/docs/lint-rules.md), [agent fence](https://github.com/PatrickOgilvie/popcomputer-web/blob/main/docs/agent-fence.md).
- **[joelhooks/rat-stack](https://github.com/joelhooks/rat-stack)** explicitly describes itself as an agentic TypeScript scaffold. Effect v4, compiler diagnostics, anti-slop rules, and agent checks make it a close philosophical comparison; its XState and Alchemy choices give it a different foundation. Source: [README](https://github.com/joelhooks/rat-stack/blob/main/README.md).
- **[vantionlabs/saas-starter](https://github.com/vantionlabs/saas-starter)** is an Effect v4/TanStack Start SaaS monorepo with Oxlint and extensive agent workflows. It is a larger product foundation rather than a small generic generator. Source: [AGENTS.md](https://github.com/vantionlabs/saas-starter/blob/main/AGENTS.md).
- **[brandhaug/b2b-saas-starter](https://github.com/brandhaug/b2b-saas-starter)** provides another enforcement precedent: local Oxlint rules run against the real linter in fixture tests. Policy tests alone therefore do not establish novelty. Source: [local Oxlint ADR](https://github.com/brandhaug/b2b-saas-starter/blob/master/docs/adr/0052-repo-local-oxlint-plugin.md).

Independent reviewer: OpenCode provider, `opencode-go/deepseek-v4.1-flash`, `variant: high`. The parent verified the added generator READMEs and selected enforcement documentation. These additions were not installed or executed; their moving branch heads were not pinned in the first-pass snapshot below.

## Closest stack matches and adjacent examples

1. **[backpine/effect-worker-mono](https://github.com/backpine/effect-worker-mono)** — closest architecture match. Its pnpm monorepo separates domain, contracts, database, and applications; includes an Effect HTTP API, React SPA, and TanStack Start app; and shares HTTP/RPC contracts. The database uses Drizzle's first-class `effect-postgres` interface with Effect SQL PostgreSQL. Its catalog pins Effect `4.0.0-beta.70`. Unlike this starter, it is explicitly Cloudflare Workers/Hyperdrive oriented; its database service documents request-scoped connections for that environment. It presents several applications together rather than documenting a frontend-selection generator. Sources: [README](https://github.com/backpine/effect-worker-mono/blob/main/README.md), [catalog](https://github.com/backpine/effect-worker-mono/blob/main/pnpm-workspace.yaml), [database service](https://github.com/backpine/effect-worker-mono/blob/main/packages/db/src/database.ts), [database manifest](https://github.com/backpine/effect-worker-mono/blob/main/packages/db/package.json).

2. **[nmnmcc/effect-stack](https://github.com/nmnmcc/effect-stack)** — close provider-independent full-stack template. It combines Effect v4, a shared HttpApi/OpenAPI contract, Drizzle/PostgreSQL, separate backend/frontend applications, and TanStack Query. The backend manifest pins Effect and Effect SQL PG `4.0.0-rc.111`. Its frontend is React Router Framework, with Orval generating browser and SSR query clients from OpenAPI. It requires Node 24/Yarn 4 and documents Docker services, Better Auth, Redis, and S3-compatible storage. This is a more opinionated application foundation than the local starter's frontend/runtime selection. Sources: [README](https://github.com/nmnmcc/effect-stack/blob/main/README.md), [backend manifest](https://github.com/nmnmcc/effect-stack/blob/main/apps/backend/package.json).

3. **[krakcons/krakstack-template](https://github.com/krakcons/krakstack-template)** — especially relevant for both Effect UI integration and automated guardrails. It combines Bun, TanStack Start, Effect HTTP, Effect Atom, PostgreSQL, auth, and localization. Its manifest pins Effect `4.1.0` and patches Oxlint through `@effect/tsgo`; its Oxlint configuration extends Effect's recommended preset and adds custom rules against unsafe assertions and other patterns. Guardrails are therefore not unique to this project. Important discrepancy: its README still describes Drizzle and an old database path, but the current manifest has no Drizzle dependency, the tree lacks that path, and `src/lib/database.ts` constructs an Effect `PgClient` layer directly. Treat the Drizzle claim as stale/unverified. Sources: [README](https://github.com/krakcons/krakstack-template/blob/main/README.md), [manifest](https://github.com/krakcons/krakstack-template/blob/main/package.json), [lint configuration](https://github.com/krakcons/krakstack-template/blob/main/.oxlintrc.json), [current database layer](https://github.com/krakcons/krakstack-template/blob/main/src/lib/database.ts).

4. **[cody9swann/effect-v4-httpapi](https://github.com/cody9swann/effect-v4-httpapi)** — closest small backend-only comparison. It provides Bun, Effect v4 HttpApi, OpenAPI, typed errors, services/repositories, Drizzle, migrations, and API-flow tests. Its manifest uses Effect `^4.0.0-beta.48`. Persistence is SQLite through `bun:sqlite` and `drizzle-orm/bun-sqlite`; its scoped database wrapper uses `Effect.tryPromise`, rather than the first-class Drizzle Effect PostgreSQL driver. It supplies neither a frontend nor the documented runtime/frontend generator matrix. Sources: [README](https://github.com/cody9swann/effect-v4-httpapi/blob/main/README.md), [manifest](https://github.com/cody9swann/effect-v4-httpapi/blob/main/package.json), [database implementation](https://github.com/cody9swann/effect-v4-httpapi/blob/main/src/infra/Database.ts).

5. **[kitlangton/effect-stack](https://github.com/kitlangton/effect-stack)** — compact full-stack Effect reference, distinct from `nmnmcc/effect-stack`. React 19/Vite communicates with a Bun backend through typed WebSocket RPC, with shared contracts and Effect SQL SQLite. Its manifest uses Effect `^3.18.4`, Biome, and the Effect language-service patch. Useful as a small end-to-end example, but its Effect generation, transport, database, and fixed application shape differ substantially. Sources: [README](https://github.com/kitlangton/effect-stack/blob/main/README.md), [manifest](https://github.com/kitlangton/effect-stack/blob/main/package.json).

6. **[AmanVarshney01/create-better-t-stack](https://github.com/AmanVarshney01/create-better-t-stack)** — strongest adjacent generator comparison. It scaffolds selectable frontends (including React/TanStack Start and none), runtimes (Node/Bun/Workers), ORMs (including Drizzle), and databases (including PostgreSQL). Its documented backend/API choices are Hono/Express/Fastify/Elysia/Self/Convex and tRPC/oRPC, rather than Effect HttpApi. It also supplies an agent plugin and skills. This supports comparing generator UX and configuration compatibility, while this starter's narrower differentiator is an Effect-first backend and enforced execution boundaries. Source: [README](https://github.com/AmanVarshney01/create-better-t-stack/blob/main/README.md). Effect support was not documented in the inspected choices; this is not proof that no experimental integration exists elsewhere.

## Additional context

The official **[Effect-TS/examples create-effect-app](https://github.com/Effect-TS/examples/blob/main/packages/create-effect-app/README.md)** already provides interactive/noninteractive generation of basic, CLI, monorepo, and HTTP-server examples. An Effect generator itself is not novel; the local frontend/runtime matrix and database-integrated application architecture are the more specific comparison.

**[effect-app/boilerplate](https://github.com/effect-app/boilerplate)** is another credible Vue-side comparison: its README documents Nuxt plus an API, and its current [frontend manifest](https://github.com/effect-app/boilerplate/blob/main/frontend/package.json) uses Effect v4, Effect Atom Vue, and TanStack Vue Query. Its [API manifest](https://github.com/effect-app/boilerplate/blob/main/api/package.json) includes the separate `effect-app` framework, Express, SQLite, and Azure SDKs. This was a manifest-level check; its complete persistence and deployment architecture were not audited.

## Assessment and limits

The clearest positioning is the combination: a small, provider-neutral Effect v4 application generator with shared HttpApi contracts, Drizzle/Effect SQL PostgreSQL, frontend choices including Vue and none, independent package-manager/runtime choices, and checked execution-boundary rules. Several repositories overlap heavily; avoid claims such as “the first Effect full-stack starter” or “the only starter with Effect lint rules.” No inspected comparison documented this exact combination, but this search cannot establish uniqueness across GitHub.
