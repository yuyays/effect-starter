# Practices worth borrowing from T3 Code and OpenCode

Researched **2026-11-07**. Recommendations only; no implementation or test execution.

The best next steps are: gate generator releases on checks of the selected tag, prove cancellation reaches server work, and close the narrow timer-wait gap in unit-test lint. Keep the current small application/contracts split. Neither upstream's product architecture nor its full lint configuration belongs in this generator.

## Existing capabilities that should not be proposed again

- **Ownership and cancellation:** [API main](../../apps/api/src/main.ts) launches scoped server/database layers; [shutdown tests](../../apps/api/src/server.integration.test.ts) prove graceful shutdown with in-flight and continuously polling keep-alive clients. [React query adapter](../../apps/web/src/lib/users.ts) and [Vue adapter](../../packages/create-effect-starter/frontends/vue/src/lib/users.ts) forward Query's signal to Effect. Both have tests observing the fetch signal being aborted.
- **Errors and spans:** [database adapter](../../apps/api/src/db/client.ts) preserves causes in `DatabaseError`; [users service](../../apps/api/src/services/users.ts) uses `Effect.fn`, logs failures, and maps them to a public error. [HTTP tests](../../apps/api/src/http.test.ts) cover typed 500 responses and invalid rows.
- **Architecture enforcement:** the [workspace rule](../../tools/oxlint/workspace-imports.js) reads package manifests and public exports, blocks application imports, and rejects cross-workspace source paths. Runtime boundaries, schema compiler hoisting, suppression explanations, anti-slop rules, and negative policy fixtures already exist. Commit `7f98509` is part of the baseline, not a recommendation.
- **Test foundations:** API tests use `@effect/vitest`; module mocking and wall-clock reads are restricted; [API Vite config](../../apps/api/vite.config.ts) separates unit/integration projects. Configuration tests inject `ConfigProvider` and filesystem services instead of mutating global configuration.
- **Generator and dependency hygiene:** [generated-project CI](../../.github/workflows/generated-projects.yml) covers React, Start, Vue, and API-only outputs. [verification](../../packages/create-effect-starter/verify-generated.js) runs outside the repository, removes generated `AGENTS.md` before checks, verifies production JavaScript, and exercises Node/Bun combinations. [pnpm workspace config](../../pnpm-workspace.yaml) has a one-day release age, build allowlist, catalogs and overrides. [Bun conversion](../../packages/create-effect-starter/package-manager.js) emits its equivalent release age and explicit trusted dependencies. [Dependabot](../../.github/dependabot.yml) groups coupled toolchains and Effect updates. Frozen installs and CI cancellation already exist.

## Seven candidates

| Candidate                                            | Local status                                                                                            | Value / incremental cost                                  | Decision                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------- |
| 1. Verify server-side cancellation and cleanup       | Ownership, shutdown, and client abort already present; server cancellation contract untested            | High / small focused integration fixture                  | **Adopt now**, rank 2                                          |
| 2. Composable observability and defect reporting     | Typed errors, service spans and error logging present; explicit configurable observability layer absent | Medium / moderate configuration and operational surface   | **Later**                                                      |
| 3. Reject timer-based waits in unit tests            | Clock reads and manual runtimes restricted; timer waits are a separate gap                              | Medium / small if limited to direct timer forms           | **Adopt now**, rank 3                                          |
| 4. Isolate inherited subprocess configuration        | Temporary projects and injected app config present; tool subprocesses inherit host environment          | Medium / moderate cross-platform and package-manager care | **Later**                                                      |
| 5. Gate releases on the exact source being published | Strong PR CI and archive smoke checks present; release job has no full-check dependency                 | High / small-to-moderate CI work                          | **Adopt now**, rank 1                                          |
| 6. Bound agent context and expose focused commands   | Small AGENTS file and selectable test projects already present                                          | Low today / new budget machinery adds maintenance         | **Skip** formal budgets; preserve concise guidance             |
| 7. Expand modular packages and runtime interfaces    | Public contracts and manifest-aware boundaries already present                                          | Low today / high abstraction and generator cost           | **Skip** package proliferation; revisit with a second consumer |

### 1. Prove cancellation at the server boundary

**Upstream observation.** T3 Code's [process runner](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/processRunner.ts) places process use inside `Effect.scoped`, bounds it with a timeout, and passes `forceKillAfter` to the spawner. Its [tests](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/processRunner.test.ts) inject `ChildProcessSpawner`, test output limits, and coordinate stdin/exit through `Deferred`. OpenCode's [server fixture](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/server/test/fixture/server.ts) uses a real server on port zero with in-memory storage and background/network features disabled.

**Local distinction.** Client cancellation tests prove the fetch signal aborts; shutdown tests prove in-flight requests can finish during server shutdown. Neither proves that disconnecting one client interrupts that request's backend fiber and runs its finalizer. This is a coverage gap, not evidence of a runtime leak. No first-party SDK integration exists that justifies adding an SDK wrapper or general process service.

**Transfer.** Add one real HTTP disconnect test using the existing server fixture style, with an injected `Database.selectUsers` Effect that signals entry and waits interruptibly. Observe cleanup through a finalizer. Keep this in `*.integration.test.ts`. Use `Deferred` for milestones; a live timeout is only the failure bound. Do not assert PostgreSQL wire-level query cancellation from a fake database seam.

**Value/cost.** It verifies the most consequential missing lifecycle contract with little generated code. A new generic background-job framework would cost far more and has no current consumer.

### 2. Add observability only when there is an operational consumer

**Upstream observation.** T3 Code's [Observability layer](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/observability/Observability.ts) composes local tracing, optional OTLP exporters, resource attributes and exporter flushing. Its [DefectReporter](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/observability/DefectReporter.ts) filters RPC reporting to unignored defects; the [behavior test](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/observability/DefectReporter.test.ts) verifies logging and a surviving sibling subscription. OpenCode's [observability factory](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/util/src/observability.ts) builds layers and falls back to local logging; its [logging implementation](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/util/src/observability/logging.ts) formats structured messages, spans and annotations, and owns periodic trimming with a scoped fiber.

**Local distinction.** The starter already has meaningful spans and typed error translation. `main.ts` has no explicit logger/exporter layer; service failures are logged in `users.ts`. This inspection does **not** establish that default Effect HTTP handling silently loses defects. The upstream reporter specifically addresses RPC; copying it into this HTTP API would require separate justification.

**Transfer later.** When a consumer needs machine-readable production logs, add one API-owned layer with a configurable level and structured console format. Specify whether the service or boundary owns each failure log; preserve public-error redaction. Add optional OTLP only after someone needs an exporter. Verify emitted records through an injected logger and flush-on-shutdown through a fake exporter. Avoid persistent local log files, rotation, heap attribution, browser forwarding, and a new shared observability package.

**Value/cost.** Useful for deployed applications, but materially more configuration and failure policy than this small generator currently needs. Basic logging is already available.

### 3. Close the timer-wait gap without copying upstream's whole rule

**Upstream observation.** T3 Code's [real-time wait rule](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/oxlint-plugin-t3code/rules/no-real-time-wait-in-tests.ts) distinguishes test runners, timer imports and driven TestClock use. Its [rule tests](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/oxlint-plugin-t3code/rules/no-real-time-wait-in-tests.test.ts) exercise aliases, helper functions and mixed clocks. Its [polling-loop rule](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/oxlint-plugin-t3code/rules/no-polling-loop-in-tests.ts) points tests toward Deferred/Queue/stream milestones. OpenCode also [registers rule fixtures](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/script/ast-grep/sgconfig.yml) and [runs lint-rule checks in CI](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/.github/workflows/check-test.yml).

**Local distinction.** `starter/no-wall-clock-in-tests` checks Date/time reads, not waits. `starter/test-runtime` prevents manual runners, while the compiler fixture checks global timers in Effect workflows. Those do not establish a policy against `await new Promise(resolve => setTimeout(resolve, 50))` in a plain frontend unit test or imported `node:timers/promises` delays. Existing API integration tests deliberately need live time; generator startup verification deliberately polls real processes. These are appropriate exceptions, not defects to remove.

**Transfer.** Start with just two recognizable unit-test forms: promise-wrapped global timer waits and imported timer-promise waits, resolving bindings to avoid shadowed-name false positives. Scope to app/contracts unit tests; exclude integration fixtures and generator/tooling tests. Keep `vi.waitFor`/browser assertions and TestClock-driven effects allowed. Use the existing real-linter policy harness; no second lint engine is warranted. Do not copy the upstream file-level heuristic that merely finding `TestClock.adjust` proves all sleeps are driven.

**Value/cost.** Agents can otherwise add slow and load-sensitive waits despite the apparent clock policy. The direct-form rule is a small extension; full interprocedural polling and clock analysis is not.

### 4. Make tool subprocess environments deliberate

**Upstream observation.** OpenCode's [environment fixture](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/core/test/fixture/environment.ts) wraps the real spawner to record external commands rather than replacing modules. Its [temporary global layer](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/core/test/fixture/global.ts) owns temporary paths through `acquireRelease`; its [temporary-directory helper](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/core/test/fixture/tmpdir.ts) exposes scoped and async-disposal forms. Its [environment helper](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/core/test/fixture/env.ts) restores modified variables after use. T3 Code's [deterministic runtime](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/orchestration-v2/testkit/DeterministicRuntime.ts) supplies TestClock and seeded Random.

**Local distinction.** API config tests are already isolated via explicit providers, and generator projects have temporary roots and `finally` cleanup. However, `verify-generated.js` and `install.test.js` spread `process.env` into spawned commands. A temporary project alone does not isolate package-manager user configuration. This is a potential source of host-dependent results; no actual failure was reproduced.

**Transfer later.** If developer/CI differences appear, pass child-only config paths and deliberate app configuration. Preserve necessary PATH, platform variables, certificates, proxy and registry settings; do not blindly empty the environment or mutate the parent process. Do not add a global `withEnv` helper for concurrent tests: restoring values does not make process-wide mutation concurrency-safe. A meaningful acceptance test would show that a hostile fixture user config cannot redirect a child test, while the caller's configuration remains unchanged.

**Value/cost.** Useful for installer reliability, but a careful cross-platform package-manager fixture costs more than a blanket environment reset suggests. Seed Random only when code actually uses randomness; there is no current need for a replay framework.

### 5. Validate the selected release source before publishing

**Upstream observation.** T3 Code's [release workflow](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/.github/workflows/release.yml) resolves a source commit, checks out that ref in quality/test jobs, and requires those jobs to succeed before `release`. It also generates archive checksums. OpenCode's [check workflow](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/.github/workflows/check-test.yml) separately verifies packed artifacts, generated clients/OpenAPI, library builds, and compiled service lifecycles. The transferable practice is checking the source and artifact that will ship.

**Local distinction.** Local release checks out `inputs.tag`, runs generator tests, packs a `.tgz`, and invokes it for React/Start/Vue with `--no-install`. That is good packaging coverage. It does not run lint/typecheck/browser/build/generated-project validation on that tag, depend on successful checks for its resolved SHA, or exercise `--framework none` in the archive loop. Main-branch CI and PR CI cannot prove that an arbitrary manually selected tag passed checks. `gh release --verify-tag` verifies tag existence, not CI success.

**Transfer.** Resolve the tag to a commit once and reuse it for validation and packaging. Prefer reusing existing check definitions; fail closed if required checks for that source are missing, failed or canceled. Include API-only in packed CLI smoke coverage. A checksum asset can wait: it supports manual integrity checks but does not itself authenticate a compromised release.

**Value/cost.** High: the released generator is the user's entry point. Additional runner time is acceptable; do not inherit nightly channels, desktop matrices, custom runners, npm trusted publishing, or upstream's release orchestration.

### 6. Keep agent ergonomics small and executable

**Upstream observation.** T3 Code measures advertised context in [AgentContextBudget.test.ts](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/apps/server/src/provider/AgentContextBudget.test.ts), then [compares budgets against main](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/.github/workflows/agent-context-budget.yml) with a maintainer-label exception. OpenCode's [root scripts](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/package.json) and [Bun configuration](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/bunfig.toml) explicitly prevent running all tests from root.

**Local distinction.** This generator has a short AGENTS file and a useful root `test` contract. Generated verification explicitly removes AGENTS before checking enforcement. API unit/integration projects are already selectable.

**Decision.** Skip formal prompt-byte budgets, approval labels, model/provider instructions, and a root-test prohibition. Preserve short instructions and make focused package/project commands discoverable when documentation needs updating. T3 Code's measured context is its own product's tool/prompt surface, not evidence that this starter needs a budget for repository instructions. Cost exceeds current value.

### 7. Preserve public interfaces; resist speculative packages

**Upstream observation.** T3 Code's [contracts manifest](https://github.com/pingdotgg/t3code/blob/6577c6b6185167c0e502fa01f9e8e8f2dee6ff25/packages/contracts/package.json) declares explicit root/settings/relay exports and depends on Effect. OpenCode's [util manifest](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/util/package.json) exposes a broad wildcard plus conditional internal imports for Bun/Node/workerd; its [observability module](https://github.com/anomalyco/opencode/blob/714d653fbb56cfb19ac90bfe6be67a90633f0300/packages/util/src/observability.ts) illustrates shared runtime assembly.

**Local distinction.** Contracts already expose explicit public paths; applications remain private and the new rule enforces that boundary. Database implementation and runtime composition stay in `apps/api`, as AGENTS requests. The API [build config](../../apps/api/vite.config.ts) deliberately bundles workspace TypeScript for production; generated verification runs Node with type stripping disabled to validate that deployment boundary.

**Decision.** Skip a generic util/domain/database/runtime package and avoid broad wildcard exports. Extract a backend implementation only when a second real backend consumer needs it. OpenCode's multi-runtime conditional imports solve a larger product's needs; selectable Node/Bun startup scripts do not justify that machinery here. Architecture lint, export maps and production resolution checks are already stronger local answers than adding packages.

## Top three: concrete proposals and acceptance criteria

1. **Release validation tied to the selected tag (candidate 5).** Resolve the tag once, validate and package that same SHA, and require the applicable existing lint, format, typecheck, unit/integration, browser, build, and generated-project checks before publication. A selected source with missing/failed/canceled required checks must not reach `gh release create`; a passing source must produce the packed CLI, with all four framework modes smoke-tested from the archive. Reuse checks rather than maintain a second divergent command list. This protects every generated project without adding application complexity.
2. **Server cancellation contract (candidate 1).** Once a real request has reached an injected waiting database operation, disconnecting that client must interrupt the operation and execute its finalizer once, inside a bounded live-test timeout. Use entry/cleanup signals instead of timing guesses. A separate health request must still succeed, and server teardown must complete. Retain the existing successful graceful-shutdown behavior. No SDK, process framework, or production route is required. This verifies end-to-end ownership beyond the already-tested client abort signal.
3. **Narrow unit-test wait rule (candidate 3).** Real-linter fixtures must reject direct promise-wrapped global timer waits and aliased/namespace `node:timers/promises` waits in app/contracts unit tests. Fixtures must accept shadowed unrelated functions, fixed dates, TestClock-driven Effects, event milestones, and the intended browser retry APIs. Existing socket integration and generator process tests must remain supported through explicit scope exclusions. Do not attempt whole-program clock analysis or ban all polling. This makes a small existing policy gap executable at agent-edit time.

These are proposals for later implementation, not changes made by this report. If timer enforcement grows into an upstream-sized analyzer, defer it; its value depends on keeping the rule small and explainable.

## Research limits

- Read-only source inspection, not a runtime, benchmark, security, dependency, or complete repository audit. No installs, broad tests, release attempts, or upstream applications were run. Workflow dependencies were inspected; successful workflow execution was not independently established.
- Upstream source is pinned for reproducibility, but recommendations are judgments for this small generator. Shared Effect v4 terminology does not guarantee API compatibility between the snapshots and local dependencies.
- Some speculative paths from older layouts did not exist: OpenCode's former `packages/opencode/test/...` paths are replaced by the inspected `packages/core/test/...` layout; T3 Code has `processRunner.test.ts`, not the guessed `processRunner.integration.test.ts`. No claims rely on those missing files. The T3 process tests inspected do not prove real OS process termination on cancellation.
- Local framework cancellation is already tested at fetch-signal level. PostgreSQL cancellation, unexpected HTTP defect reporting, and host configuration interference remain unverified; the report deliberately distinguishes missing evidence from demonstrated bugs.
- No second opinion was obtained: the requested research sub-agent performed the work itself, with no delegation, as instructed. No alternative reviewer/model was substituted.
- Only this report was written. Code, configuration, AGENTS files, and existing research were left untouched; no commits were made.
